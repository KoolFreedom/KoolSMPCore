# Contributing to KoolSMPCore

We appreciate your interest in contributing to KoolSMPCore.

Some basic information can be found [on our forums](https://koolfreedom.eu.org/d/4-koolfreedom-developer-information), but this file goes over a few extra guidelines.

# How to contribute
* Open an issue before starting major work so the maintainers can confirm the direction.
* Make sure that your changes align with the guidelines found in the forum post linked above
* Follow the existing code style and project structure
* Test your changes locally before pushing to GitHub and before opening a Pull Request.
* Include a clear description of what your changing and why.

# Pull Requests
* Create a branch for your work. Name it something like `feat/<your_change>` or `fix/<your_fix>`. If you use `main` or `dev`, that's okay, just be ready to sync your fork if needed
* Keep commit messages clear and specific
* Submit your PR with a brief summary of your work, include relevant screenshots/logs and other necessary information.
* Be open to feedback and adjust properly.
